## Правки в процессе сборки (в этой же сессии, до сдачи)
- **Число-ревил «600 000» не влезало в карточку A** на кегле 150 (877px против
  ~810px доступных с отступом 30px) — автопроверка `check_text_outside_card`
  поймала 1 кадр с текстом за левым краем карточки. Исправлено: кегль для этого
  числа снижен до 128 (747px, влезает с запасом), у каждого числа в `NUMS` теперь
  свой `size`. Пересобрано, автопроверка повторно прогнана — 0/579.
- **Первая версия `CAPS`/`SHOTS` была набрана по `.srt`-таймкодам фраз, а не по
  пословным таймингам** — при сверке с `source.json` обнаружилось расхождение:
  несколько границ фраз/резов не совпадали ни с началом, ни с концом ни одного
  слова (например «продували её» была сдвинута на речь следующего предложения
  «месяцы работы и»). Это нарушало жёсткое правило «рез/субтитр — строго по
  словам». Весь `CAPS` и все резы `SHOTS` пересобраны заново по пословным
  таймингам из `source.json`; скрипт-проверка подтвердила 0 несовпадений границ
  фраз со словами и 0 резов вне границ фраз.
- Смысловые правки распознавания (тайминги слов не менялись): «провессии» →
  «профессии» (опечатка распознавания), «сажет» → «сжигает» (двигатель топливо
  сжигает, а не «сажает» — фонетически близко), «работки» → «работы».
- Громкость: однопроходный `loudnorm` дал -14.80 LUFS / -1.32 dBTP. Проверено
  несколько вариантов доп. прохода `volume+alimiter`; выбран
  `volume=0.55dB,alimiter=limit=0.78` → **-14.52 LUFS, -1.94 dBTP** — вариант с
  большим приближением к -14 (`volume=1.0dB,alimiter=limit=0.75` → -14.27 LUFS)
  давал истинный пик -0.32 dBTP, что нарушает лимит ≤-1 dBTP, поэтому отклонён
  в пользу более безопасного по пику варианта (правило delivery-specs.md:
  «если итерация ловит и громкость, и пик — не отдавать, вернуть предыдущую,
  которая прошла по пику»).
