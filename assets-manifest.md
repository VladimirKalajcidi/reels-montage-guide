# Assets Manifest — где что лежит, чем наполнять кадр

Чтобы бралось из библиотеки, а не «изобреталось».

## 0. Где что лежит
| что | путь |
|---|---|
| исходник ролика | `videos/<папка>/source.mov` |
| музыка | `audios/` |
| скачанный сток | `videos/<папка>/stock/stock_<id>.mp4` |
| скрипты сборки | `build/` (`style.py`, `graph.py`, `storyboard.py`, `render.py`, `sfx.py`, `plan.py`) |
| готовый ролик | рядом с исходником, `<тема>_edit.mp4` |

## 1. Транскрипция
**OpenAI Whisper API** — основной способ (добавлено 2026-09-24). Ключ в `build/.env`
(`OPENAI_API_KEY`).

- `POST https://api.openai.com/v1/audio/transcriptions`, заголовок `Authorization: Bearer <KEY>`,
  тело `multipart/form-data`: `file=<аудио/видео>`, `model=whisper-1`, `language=ru`,
  `response_format=verbose_json`, `timestamp_granularities[]=word`
- Ответ содержит `words: [{word, start, end}, ...]` — это и есть пословные тайминги для
  `words.json` (см. `START-HERE.md`, блок 1). Исходный `.mov` можно отправлять целиком,
  **только если он меньше 25 МБ** — лимит API (иначе ответ `413: Maximum content size limit`).
  Больше — вынуть звук: `ffmpeg -i source.mov -vn -ac 1 -ar 16000 -c:a pcm_s16le voice16k.wav`
  (≈1.6 МБ на минуту; ролик 15: `.mov` 51с весил 26.3 МБ).
- Стоимость — доли цента за короткий ролик (~$0.006/минуту).

**Локальный `whisper`** — запасной вариант без ключа/сети (медленнее на CPU):
`whisper <файл> --language ru --model medium --word_timestamps True --output_format srt`.
Для ускорения — `faster-whisper` или `whisper.cpp` (см. `README.md`).

## 2. Шрифты
**Фактически используются системные шрифты macOS** — ставить ничего не нужно, кириллица полная:

| роль | файл | зачем |
|---|---|---|
| основной гротеск | `/System/Library/Fonts/SFNS.ttf` (вес 500) | весь поток субтитров, числа, крупные слова |
| наклонный гротеск | `/System/Library/Fonts/SFNSItalic.ttf` | редкие выделения внутри строки |
| акцентный serif italic | `/System/Library/Fonts/Supplemental/Baskerville.ttc`, индекс 2 | смысловые слова: *вероятность*, *невозможно*, *гарантия* |

Baskerville Italic по рисунку очень близок к засечному курсиву из эталонов — высокий контраст,
каплевидные окончания. Проверено на кадре.

Альтернатива, если понадобится ставить шрифты вручную: **Onest** + **Playfair Display Italic**
(обе свободные, OFL). Платный Gilroy чуть ближе к эталону геометрически, но на кадре разница не видна.

Признаки, по которым проверять основной шрифт: одноэтажная «а» (круг + прямая стойка), круглая «о»,
высокая x-height, монолинейный штрих, «9» = круг с прямым хвостом.

## 3. Видео-вставки

### Общее правило: только видео
Фото и стоп-кадры не используем ни в одном рецепте. Два исключения, оба — только подлинный
документ (портрет/архивный кадр/скриншот публикации), не декоративный сток-портрет «под
настроение»:
- **R8** (пруф) — обложка журнала, скриншот статьи, исторический кадр, портрет, страница
  учебника; полноэкранный, рамка снимается, **не чаще одного раза за ролик**.
- **R11** (фото конкретного человека/объекта, добавлен 2026-09-24) — та же природа фото, но в
  обычной карточке B наравне с видео-вставками, рамка на месте, **1–3 раза за ролик и только
  когда фото по смыслу удачнее видео** (называют конкретного узнаваемого человека или объект) —
  не на каждое упомянутое имя, это не автоматика.

Искать такие фото — Wikimedia Commons (архивные снимки, портреты) и официальные страницы
изданий (обложки, скриншоты статей); проверять подлинность и соответствие подписи.

### Изоляция материалов по роликам
**Стоковые видео не переиспользуются между разными роликами.** Каждый ролик хранит свои смысловые
вставки рядом с исходником: `videos/<папка>/stock/`. Общая папка `build/assets/` не является библиотекой
стока для новых проектов; там могут лежать только технические временные файлы движка и кэш текущей
сборки. Если клип был скачан или подготовлен для `videos/5`, он не используется в `videos/6`.

Если под конкретную тему нет очевидно релевантного живого видео, **не ставь сток ради ритма**.
Лучше заменить план на R4/R10 и дорисовать собственную графику по смыслу. Для математических задач
с предметной механикой (палка, отрезки, квадрат вероятностей, геометрия) графика обычно лучше стока.

### Стратегия подбора — смешанная
| источник | когда берём |
|---|---|
| **фрагмент фильма** | когда кадр реально узнаваемый и работает как мем/отсылка. Держать ≤3с. |
| **лицензионный сток** (Pexels, Pixabay, Mixkit, Coverr, Envato) | классы, аудитории, толпа, руки, доска, ноутбук, город — всё «фоновое» |
| **своя графика на сетке (R4/R10)** | любая математика: схемы, формулы, деревья, графики, комбинаторика |
| **AI-видеогенерация** | когда под смысл нет ни кино-кадра, ни стока |

Приоритет: если сцену можно закрыть **своей графикой без потери смысла — берём графику**.
Сток берём только когда он прямо относится к произносимому смыслу.
Кино оставляем для тех 3–5 кадров за ролик, где узнаваемость и есть эффект.
Это снижает риск ограничений по монетизации, не ломая стиль.

### Кино-сток — что резать под математику
Эталоны берут узнаваемые кадры из фильмов. Рабочая библиотека под математическую тему:

| тема | откуда брать |
|---|---|
| гений/озарение/формулы на стекле | **Игры разума**, **Умница Уилл Хантинг**, **Одарённая** |
| школа/класс/экзамен | **Общество мёртвых поэтов**, **Хористы**, **Гарри Поттер** (класс), любой школьный сериал |
| вычисление/расшифровка/код | **Игра в имитацию**, **Матрица** (поток цифр), **Социальная сеть** |
| вероятность/ставки/казино | **21**, **Шулера**, **Большая игра**, **Казино Рояль** |
| наука/доска/лекция | **Человек, который познал бесконечность**, **Теория всего**, **Интерстеллар** |
| реакция/абсурд/эмоция | комедийные мемные кадры (танец, шок, «вау») — для рецепта R3 |

Правила отбора:
- Кадр должен читаться **за 0.5 секунды** без контекста.
- Кадр всегда **играет**, не стоп-кадр.
- Никакого мелкого текста в кадре — он не читается в карточке 858px.
- Кадр притемняем на 25–30% (см. `brand-kit.md §6`).
- **Юридически:** фрагменты фильмов в таком формате — стандартная практика для соцсетей, но это не лицензия.
  Риск клейма и ограничения монетизации есть. Держим фрагменты ≤3с, не больше **3–5 кино-вставок на ролик**,
  и никогда не строим ролик целиком из чужого материала.

### Где брать сток
**Pexels API** — основной источник наравне с Pixabay (оба настоящие API, не скрапинг). Ключ
лежит в `build/.env` (`PEXELS_API_KEY`, не хранить в файлах гайда/раскадровок — личный ключ).

- поиск видео: `GET https://api.pexels.com/videos/search?query=<запрос>&orientation=landscape&per_page=15`
  — ключ передаётся заголовком `Authorization: <KEY>` (не query-параметром)
- фильтры: `orientation` (`landscape` разумен для карточки B, 1.385:1 ближе к горизонтали),
  `size` (`large`/`medium`/`small` по минимальной высоте)
- ответ даёт массив `video_files` с разными разрешениями и прямым `link` — брать то, что ближе
  к 1280×720 и выше, смотреть `duration` в секундах в самом объекте видео для проверки после
  скачивания
- **атрибуция не обязательна** по лицензии Pexels, но источник клипа всё равно фиксировать в
  монтажном листе

**Pixabay API** — второй основной источник, дополняет Pexels там, где по конкретному запросу
ничего внятного не нашлось. Ключ лежит в `build/.env` (`PIXABAY_API_KEY`).

- поиск видео: `GET https://pixabay.com/api/videos/?key=<KEY>&q=<запрос>&video_type=film`
  (полезные фильтры: `category` — есть `science`, `industry`, `education`, `computer`, `business`;
  `min_width=1280` для приличного качества; `order=popular` по умолчанию разумен)
- ответ даёт несколько разрешений (`large`/`medium`/`small`/`tiny`) с прямым `url` — скачивать
  `large` или `medium`, брать `duration` из ответа для проверки после скачивания
- **лимит** 100 запросов/60с на ключ, **систематический массовый обход запрещён условиями
  сервиса** — это нормально для точечного подбора под один ролик (десяток запросов), но не для
  скачивания «на будущее про запас»
- **атрибуция:** если результаты поиска показываются самому пользователю (не наш случай — мы
  вставляем видео в готовый ролик) — атрибуция не нужна на итоговом видео, но сам факт, откуда
  клип, всё равно фиксировать в монтажном листе

**Pixabay Images** — тот же Pixabay-ключ, эндпоинт `https://pixabay.com/api/?key=<KEY>&q=<запрос>` —
пригодится для фото R8/R11 (см. `shot-recipes.md`), не для обычных видео-вставок.

**Mixkit** — запасной источник, если под конкретный запрос ни на Pexels, ни на Pixabay ничего
внятного не нашлось:
свободная лицензия, коммерческое использование без атрибуции, но **без официального API** —
поиск идёт по HTML-странице, которая часто отдаёт Cloudflare-проверку вместо результатов
(нестабильно, много неудачных попыток на реальном разборе видео 9).
- поиск: `https://mixkit.co/free-stock-video/<запрос>/` → со страницы вытащить id клипов
  (если страница вернула ~5-6 КБ «Just a moment…» — это блокировка, не пустой результат;
  повторить попытку позже или искать через уже закешированные категории)
- скачать: `https://assets.mixkit.co/videos/<id>/<id>-1080.mp4` (если 403 — пробовать `-720`)

Скачанное для одного ролика не становится библиотекой для следующего. Если нужен сток — скачай его
в папку конкретного ролика (`videos/<папка>/stock/`) и укажи источник в монтажном листе.

**Проверять скачанное, а не доверять коду ответа.** У Mixkit изредка `-1080.mp4` отдаёт
`200 OK`, но с совершенно посторонним роликом (не тем, что на странице и в `-720.mp4`) —
не ошибка сети, а битые данные на их CDN. Пример: клип 5886 «girl-walking-to-school»
на `-1080` отдал ролик с каплей мёда на решётке, 12с, тогда как настоящий — 21с девочка
с рюкзаком у школы (совпадает с `-720`). Признак — длительность файла не совпадает с
длительностью на странице клипа (`"duration":"PTxMxS"` в html). После скачивания сверять
длительность и хотя бы один кадр с описанием/превью со страницы, а не только код ответа
и что файл открылся.

## 5. Звук
SFX **синтезируются кодом** (`build/sfx.py`), библиотека не нужна:

| звук | как сделан | уровень от пика голоса |
|---|---|---|
| low whoosh | шум через ФНЧ 180 Гц + слабый свип 140→34 Гц | **0.040** |
| impact | синус 92→41 Гц с затуханием + короткий клик | **0.070** |
| soft tick | шум с быстрым затуханием + 1.4 кГц | **0.030** |

- Уровни выше — уже исправленные. Изначальные (0.13 / 0.22 / 0.10) оказались втрое громче
  и **били по ушам**. Не поднимать обратно.
- Сабовая часть whoosh — не громче 0.45 от шумовой. Именно низ и раздражает.
- **Где брать фоновую музыку** (исследование 2026-09-24): Pixabay Music (бесплатно, ключ API тот же;
  у части треков Content ID — претензия снимается сертификатом лицензии Pixabay), Uppbeat (3 трека/мес
  бесплатно, нужна атрибуция; платно до ~$14/мес), Epidemic Sound (~$18/мес, один канал на площадку),
  Artlist (годовая подписка, бесплатного нет), Bensound / Soundstripe / Motion Array; внутри Instagram —
  Meta Sound Collection. **YouTube Audio Library не брать** — лицензия чистая только на YouTube.
  Под наш формат: ambient tech / minimal electronic / lo-fi, 90–115 BPM, без вокала и резких ударных.
  У ролика-образца конкурента подложка ≈ фа-диез минор, ~110 BPM, на ~16 дБ ниже голоса. Опознать трек
  кодом не выйдет (ShazamKit без entitlement не пускает к каталогу) — через название звука в Reels или
  Shazam на телефоне.
- **Музыка ставится всегда**, если трек лежит в `audios/`. Уровень −19 dB от RMS голоса,
  петля с кроссфейдом 0.25с, фейд-ин 0.8с / фейд-аут 2.0с.
- Только своя / лицензированная музыка.

## 6. Генерация ассетов
- **Счётные вставки** (рецепт R7) — берём стоковое видео классов/аудиторий/толпы. Если нет подходящего —
  видеогенерация. Фото не используем: количество людей всё равно считывается из подписи, а не из кадра.
- **Прозрачные PNG** (рецепт R9): удаление фона либо генерация на `#00FF00` / `#FF00FF` с хромакеем.
  Это единственная статика, которая допустима, — она лежит поверх живого видео.
- **Математика на генерациях** — самое опасное место: модели пишут бессмысленные формулы.
  Любую формулу/число на генерации либо **проверять вручную**, либо не показывать крупно,
  либо рисовать самому на сетке (R10).
- Видео-генерация дороже картинок — подтверждать до батчей.
- **VERIFY каждую генерацию** перед вставкой: текст, формулы, руки, лица, отсутствие варпов.

## 7. Что НЕ спрашивать
Имя, канал, хэндлы площадок, аудитория, формулировка CTA — для монтажа не нужны и на экране
не появляются. Не выносить в вопросы.
